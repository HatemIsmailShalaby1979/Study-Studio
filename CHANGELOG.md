# Changelog

All notable changes to Study Studio are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - Unreleased

### Added
- AI Runtime abstraction with pluggable providers. LM Studio is a **native** provider (`src/lib/ai-runtime/providers/lmStudio.ts`) speaking its REST API v1, with v0 and OpenAI-compatible fallbacks for older servers; Ollama and OpenAI/OpenRouter are also registered.
- **On-demand model loading.** Selecting a model in the dropdown loads it into memory — a downloaded-but-unloaded model is made resident automatically, with a progress indicator and a ten-minute ceiling. There is no need to preload it in the LM Studio UI first.
- **Settings shows load state per model** — a *Loaded* / *Downloaded* badge with Load/Unload actions. The badge renders only when the provider can actually report state, rather than guessing.
- **CORS-free desktop transport** (`src/lib/ai-runtime/transport.ts` via `tauri-plugin-http`): provider discovery and generation route through the Rust backend inside the desktop shell, so any local OpenAI-compatible server (LM Studio, LocalAI, vLLM, LiteLLM, FastChat) works with no server-side CORS configuration.
- **Provider selector on the Generate page** — switch between detected providers live; the model list and routing follow the selection.
- **Skill injection.** Five methodology packs (Humanizer, Education, OpenLesson, Podcast Ops, NotebookLM Studio) compose into the system prompt, routed by intent: lessons get education + open-lesson + humanizer, podcasts get podcast-ops + humanizer. Packs are bound automatically at launch and can be toggled individually on the Generate page.
- **Design system** (`DESIGN.md`) and a compiled-CSS token guard (`npm run check:tokens`) that fails the build when a Tailwind colour utility emits no CSS.
- Self-hosted typography via `next/font` (Inter for body, Geist Mono for monospace) — no network fetch at runtime.
- Learning Journey dashboard with lesson progress, quiz scores, and study streak.
- Ollama bootstrap on app mount with retry and status indicator.
- Cancellation for lesson generation: a Cancel button stops an in-flight request end-to-end via `AbortSignal`.
- Visible guidance when the AI runtime is running but has no models available.
- Confirmation dialog before deleting an individual lesson from the library.
- Dev-server warmup (`scripts/dev-warm.mjs`) that pre-compiles the app `layout` chunk, fixing a `ChunkLoadError` race when `tauri dev` opens the window.
- **Regression guards**: `check:tokens` (design tokens), `check:coverage` (per-directory coverage floors), `check:versions` (four-manifest version drift), and `lint:ci` (`--max-warnings 0`).
- **Live integration test** for the LM Studio provider (`LMSTUDIO_LIVE=1`), opt-in and hermetic by default.
- **Reasoning control in the runtime contract.** `AICompletionOptions.reasoningEffort` lets a caller ask a reasoning-capable model to answer without thinking, and `AIModel.reasoning` reports per-model what the runtime says about it (`supported`, `canDisable`, `default`) — read from LM Studio's own `capabilities.reasoning.allowed_options`, not inferred from a model name. Providers that cannot express the directive ignore it, and the runtime never assumes it was honoured.
- **Live end-to-end generation test** (`LMSTUDIO_LIVE=1 LMSTUDIO_LIVE_MODEL=<key>`): the 512-token title call, a dialogue chunk, a complete podcast script, and a `long`-length topic lesson. The unit suites mock HTTP, so they can prove the request the app builds and the response it parses but never that a real model answers a real request — which is exactly where the podcast defect lived.

### Changed
- **The Jest per-test timeout is now 15 s (was the 5 s default).** `scripts/verify.mjs` runs its seven gates concurrently, so `test + coverage` shares the machine with `next build` and the linter; a jsdom suite paying module transform plus first-render cost under that load was observed to cross 5 s. `library.test.tsx` timed out at exactly 5000 ms inside a `verify` run, passed 3/3 in isolation, and the gate went green on the next full run — a starved test, not a slow one. The default pipeline should not report scheduling jitter as a failure. This is a scheduling tolerance, not a quality bar: `verify --serial` is still the option on a loaded machine, and the coverage floors are unaffected.
- **Local runtime priority is now LM Studio first**, with Ollama as the supported alternative. `README.md`, `apps/desktop/README.md`, and `docs/OFFLINE_SETUP.md` were rewritten accordingly — they previously declared Ollama a hard requirement.
- Quiz now renders all questions at once; the single-answer mode that trapped users on question one was removed.
- Quiz evaluation failures are surfaced to the user instead of failing silently.
- Featured lesson content updated to describe the multi-provider runtime honestly (local-first, with optional OpenAI-compatible endpoints).
- Version aligned to 0.2.0 across the root `package.json`, desktop `package.json`, `tauri.conf.json`, and `Cargo.toml`, with a guard to keep them there.
- Provider routing (`computeCanGenerate`, `deriveMode`, `needsApiKey`) extracted from `AIRuntimeProvider` into pure, fully tested functions in `src/lib/ai-runtime/routing.ts`.
- `generation.ts` reduced from 1,580 to 1,469 lines; the dead `getPodcastSystemPrompt` (no production caller) was removed.

### Fixed
- **A failed voice download was written to disk as though it had succeeded, and then advertised as an installed voice.** `download_voice` never checked the HTTP status, so the response body was written regardless — and a 404 from HuggingFace is the 15-byte text `Entry not found`. Because voice discovery asked only whether the file *existed*, four such files made the app report text-to-speech as **available** while Piper could not load any of them: the user was told audio was ready and then got a failure. Confirmed on this machine — `%APPDATA%/com.studio.study/tts` held exactly those four 15-byte files. Downloads now use `error_for_status`, so a rejected download fails with the voice name and the URL instead of leaving a poisoned file behind, and discovery additionally requires a plausibly-sized model (≥1 MB, far below any real voice and far above any error body) so a truncated download is never reported as installed.
- **No voice model could be downloaded, so audiobook and podcast *audio* were unreachable in the desktop app.** The downloader built its URL as `<voice directory>` + `.onnx`, but the official `rhasspy/piper-voices` repository stores files as `<directory>/<voice_id>.onnx`. Every URL therefore pointed at a directory and returned **404** — verified live: `.../en/en_US/lessac/medium.onnx` → 404, `.../en/en_US/lessac/medium/en_US-lessac-medium.onnx` → 200. Because no voice could ever be installed, `isTtsAvailable()` stayed false permanently and the audio half of the podcast/audiobook feature could not be reached at all, on any machine, however long the user waited. The path now carries the voice id as the file name. The Rust suite also asserted only the *directory* — a test that was green the entire time downloads were broken — so it now asserts the exact URL, plus an invariant that every catalogued voice's URL ends with its own id.
- **Podcast and audiobook generation failed on every reasoning model (9B/12B/14B class), because the model spent its entire response budget thinking and never answered.** A reasoning model's thinking tokens are drawn from the same `maxTokens` budget as its answer, and the app's structured requests are deliberately small — the first podcast call is a 512-token title request, the dialogue chunks are 6-line batches. Measured live against `qwen/qwen3.5-9b` at that real budget: **512 of 512 tokens went to reasoning, `content` came back empty, `finish_reason: "length"`** — deterministically, on every attempt. The app then read the empty string as malformed JSON, classified it as a recoverable formatting slip, and retried the same model three more times, spending the same budget for the same nothing before reporting a JSON error that was never the problem. Structured generation now asks the runtime to answer without thinking (`reasoning_effort: "none"`, sent only to models whose runtime reports they can reason). The same request that returned nothing now returns valid JSON in 0 reasoning tokens and finishes **~6x faster** (2.8 s against 17.3 s). For a model whose runtime mandates reasoning, the starvation is now detected and reported as what it is instead of a formatting fault, and is no longer retried.
- **Switching models in the dropdown stacked them in memory until the next load failed outright.** LM Studio keeps every loaded model resident until its own idle TTL expires, and the app never released anything — so choosing 9B, then 12B, then 14B left all of them resident. Observed live on this machine: with a 9B and a 7B resident, loading a 12B, a 14B and a 9.4B each failed with **HTTP 500**, and the 12B and 14B attempts took **627 s and 673 s** to fail. The user saw "could not load this model into memory" on every subsequent selection, with no way to recover from inside the app. A model load now releases the previously resident model first — the app shows one selected model and generates with one, so keeping one resident is the only policy under which a second can fit. The release is best-effort: a failed release never aborts the load, and it is skipped entirely when the requested model is already resident.
- **A model load that could not possibly succeed was attempted anyway.** `AICompletionOptions.reasoningEffort` is threaded through the runtime's option merge; a request that asks for it is degraded — the directive is dropped and the request retried — only when the server actually rejects that field, rather than failing the whole request. A 400 about anything else is surfaced unchanged, so an unrelated rejection can never be misread as a reasoning problem.
- **An empty answer is no longer silently returned as a successful one.** A completion with no `content` but a full `reasoning_content` now raises `ReasoningBudgetExhaustedError` carrying the token split (`512 of 512 tokens were internal reasoning`). A genuinely empty answer with no reasoning evidence is left alone — inventing a reasoning diagnosis for an unrelated failure would be the same fabricated explanation this check exists to remove.
- **Podcasts could not be generated at all without a Piper voice installed.** The "Generate Podcast" button on the lesson page was gated on `isTts` and relabelled "🔇 TTS unavailable". Generating a podcast *script* is pure text generation — dialogue, glossary, quiz — and has nothing to do with text-to-speech; only turning that script into an MP3/WAV does. On a fresh install, where no voice model has been downloaded yet, the button was permanently dead and the whole podcast feature was unreachable. The script is now gated on the AI runtime (`canGenerate`), and the TTS notice appears only alongside the audio step it actually concerns.
- **A failed model pre-load aborted generation before it started — twice.** `LMStudioProvider.ensureModel` threw on any load failure, and it sits on the critical path of every request, so a runtime that refused the load we asked for (a window that does not fit, load guardrails, a GPU backend it cannot initialise) produced "Failed to select a model" for a model the app had successfully resolved, without ever asking the model to generate anything. Init then attempted the same load again, up to the ten-minute ceiling each time. The load is now attempted at the preferred window and, if that fails, once more at half the cap (16 384 — chosen so a rescued model can still serve the app's largest request, rather than merely loading); if it still fails, the model id is returned and the chat request becomes the authority, which is what LM Studio's just-in-time loading expects.
- **Generation was pinned to a runtime that was not running.** `AIRuntime.resolveProviderId()` fell back to "first registered provider" — Ollama on every install — so a machine running only LM Studio had every un-pinned request, and the entire init handshake, aimed at a port nothing was listening on. Resolution now prefers a provider that actually answered discovery. `LOCAL_PROVIDER_IDS` also leads with LM Studio, matching the shipped position; it had led with Ollama since 0.2.0 while the release notes claimed otherwise.
- **Launch spent 20-30 s searching for a local model that was already up.** The handshake listed models against one hardcoded provider five times, two seconds apart, *before* running discovery; then asked a runtime to start itself unconditionally — spawning `ollama serve` and polling it for up to 15 s on a machine using LM Studio. Discovery now runs first (it is the cheap, bounded call, and it decides everything downstream), the bootstrap happens only when nothing local answered, and its retry loop is 3 x 1.5 s and re-discovers instead of assuming which provider started. Provider discovery itself also runs concurrently: the old sequential loop cost the *sum* of every provider's timeout rather than the slowest one.
- **An explicit "Re-scan" was answered from a 10-second cache.** The health monitor's snapshot made the Settings button report what the app already believed rather than what was running. `refreshProviders` now invalidates it first.
- **The one-shot lesson request was retried three times before the chunked fallback.** The one-shot asks a local model for the whole lesson — 8-12 sections plus glossary and quiz, up to 24 576 tokens — in a single structured response, so a failure is deterministic: the same prompt overruns the same budget and truncates in the same place. Retrying it spent three more full generations (minutes each on a 9B model) reaching the same error, and only then ran the fallback that exists for exactly that failure. It is now attempted once; the same-model retry stays on the *chunks* of the fallback path, where a request is small enough that a second attempt can differ.
- **Cancel did nothing for an OpenAI-compatible provider.** `AICompletionOptions.signal` was accepted and then dropped by `postChatCompletion`, so the HTTP request stayed open and the model kept generating after the user cancelled. Ollama's transport had the same defect, fixed earlier; this is the other half. Cancellation is also now available for podcast generation, which can be a dozen sequential model calls and previously could only be escaped by closing the app.
- **A runtime that could not load the model showed the user its raw JSON.** The failure arrives as a 400 whose body is the server's own error, and it was surfaced verbatim as `OpenAI error (400): {"error":{"message":...`. It is now reported as "the runtime could not load this model into memory", with the two things that actually help: try a smaller model, or lower the context window in the runtime's own settings.
- **The Generate page asserted a model load that had failed.** `didLoadModel` was `!alreadyLoaded`, so a load that was attempted and failed still rendered "Loaded <model> into memory for this session". `ensureModelLoaded` now checks residency with the provider and reports `loaded: false` with guidance, and the page only claims a load that happened.
- **Drift and wasted round trips.** The Generate page carried its own copy of the local-provider id list (now imported from `ai-runtime/providerIds.ts`); LM Studio's `health()` did not stamp its model-list timestamp, so discovery re-issued the identical `GET /api/v1/models` it had just made; and the post-load residency poll ran for the full ten-minute load timeout, which the POST had already spent, rather than being bounded at 60 s.
- **Podcast hosts were always reported as male.** Host gender was derived with `voice.includes("female")`, and no real Piper voice id contains that string — they are `en_US-amy-medium`, `ar_JO-kareem-medium`, and so on. So the prompt named two men and instructed the model that "genders MUST match voices" while the voices actually selected were a man and a woman. Gender now comes from the voice catalog's own `gender` field, the same one the language switcher uses.
- **The save dialog could be opened twice.** The Save button stayed enabled while a save was already in progress, and `downloadTrack` guarded only playback, so a second click ran the file picker again — a second OS dialog. Saving is now disabled while a save is in flight, using the same predicate the state machine already applied.
- **AI quiz evaluation discarded the model's per-question explanations**, and returned one entry per *model* entry rather than one per *question* — so a short reply silently dropped questions from the results. The breakdown now always has exactly one row per question, carrying the model's explanation where it wrote one and the authored explanation otherwise. The score, the counts and the ratings are computed from the submitted answers rather than read out of the reply, so a model cannot report a score inconsistent with its own per-question results.
- **One misbehaving provider could take down discovery for every other provider.** `discoverAll` documents "Never throws" and has a per-provider error handler — but that handler called `capabilities()`, the very call that had just failed, so the exception escaped. A provider whose capability report fails now reports itself unavailable and the others are still listed.
- **A directly loaded model ignored the context cap.** `loadModel` sent `context_length` only when its caller supplied one, so any path other than the app's own loaded at the model's full window — up to 1,048,576 tokens on the models tested. It now always sends the capped value, and never more than the model reports it can hold.
- **Provider detection advertised an address that nothing serves.** LM Studio's native liveness URL was reported as `http://localhost:1234/api` after a suffix strip; it now reports the origin.
- **Removed a dead iteration bound** in chunked podcast generation. The bound could never fire — the chunk validator requires two lines, so the target is always reached first — and it read like protection against a model that under-delivers. The loop is bounded by the validator instead, and that invariant is now asserted directly.
- **60+ design-token utility classes compiled to nothing** — `bg-primary-soft`, `to-accent-blue`, `from-accent-*` and others were absent from `tailwind.config.ts`, so selected cards, accent text, and the title gradient rendered unstyled.
- **The declared typeface was never loaded.** A stray `babel.config.js` silently disabled SWC, which `next/font` requires; the file was also unnecessary because Jest transforms with `ts-jest`. Inter is now self-hosted, and the exported lesson HTML no longer names a font it cannot load.
- **`health()` reported an empty recommended model** for LM Studio while listing five models.
- **An embedding-only model could be recommended for generation** — the catalogue mixes `type: "embedding"` with `type: "llm"`.
- **The model-load timeout was 8% from failing**: loading a 4.23 GB model measured 165.9 s against a 180 s budget. Raised to 600 s.
- **`createJourney` could generate colliding ids** when `crypto.randomUUID` was unavailable (`j-<timestamp>` has millisecond resolution), so deleting one journey deleted both.
- **Silent failure when no models are available**: the runtime now reports `available: false` with a guidance message instead of appearing healthy.
- **LM Studio (and other CORS-restricted local servers) reported "Unavailable" in the desktop shell** — requests are now served by the Rust backend, bypassing the browser CORS check.
- **Switching providers could leave a stale model selection**; the Generate page now resets to the active provider's recommended model.
- **Error classification by substring matching at the UI edge** mis-reported failures — a validation error mentioning "voice" was shown as an audio failure. One classifier, in `friendlyErrors.ts`, now handles it, and auth is checked before localhost so a 401 is not reported as "server unreachable".
- **`ollama.ts` bypassed the CORS-free transport**, using raw `fetch` for two calls.
- **The `num_ctx` comment contradicted the code** (documented 8192, coded 24576).
- Dead-end single-answer quiz mode could never advance past question one or reach evaluation.
- `AbortSignal` was dropped by the Ollama transport, making in-flight generation non-cancellable.
- Deleting a library lesson could wipe it plus its quiz results and progress without any confirmation.
- A tracked file referenced an ignored one: `featured-podcast.json` pointed at `Study_Studio_Podcast.mp3` while `*.mp3` was gitignored, so the featured podcast shipped a dangling reference.
- Nine production lint warnings, and 23 false-positive `no-unused-vars` errors caused by using the non-TypeScript-aware ESLint rule.

### Removed
- **The `apps/mobile` Expo scaffold.** It was unreachable code — no tests, hardcoded to Ollama, and it duplicated lesson/audio/storage logic that had already diverged from the desktop app. The structural flaw is that a phone resolves `localhost` to the phone, so the Ollama-only design could never work on the device it was written for. The root `install:mobile` and `typecheck:mobile` scripts were removed with it.

### Security
- **Tauri CSP `connect-src` narrowed from `http://localhost:*` to the seven ports the app actually uses** (11434, 1234, 8080, 3980, 8000, 4000, 21002). The previous wildcard permitted every loopback port, so a compromised dependency could scan local services freely. Caveat: inside the desktop shell the effective gate is the capability file rather than CSP, because `runtimeFetch` routes requests through the Rust backend.
- Documented that API keys are persisted to `localStorage` in plaintext. Moving them behind the OS credential store is **permanently declined** (`AUDIT.md` 5.6): the product intentionally supports browser mode and arbitrary OpenAI-compatible providers, so a Tauri-only keychain command would make credential semantics differ by shell and still could not protect keys already handed to a browser runtime. Provider keys are treated as user-managed secrets.


## [0.1.0] - 2026-08-02

### Added
- Windows x64 release with NSIS, MSI, and portable installers.
- Lesson and podcast generation from a topic or pasted study material, fully local via Ollama.
- Structured lessons with sections, glossary, and quiz; dual-host podcast scripts with TTS playback.
- Piper TTS voice catalog (English US x2, English UK, Arabic Jordanian) with on-demand voice download and MP3/WAV export.
- Session-pinned model selection with smart model detection.
- Quiz & AI Evaluation Engine with personalized feedback.
- HTML export, library persistence, and Tauri desktop shell.
- Desktop-first release; the Expo mobile scaffold was retained but never shipped as a supported client. It was finally removed in 0.2.0.
